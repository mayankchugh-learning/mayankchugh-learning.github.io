What is CIS?
CIS = Center for Internet Security
A non-profit that publishes CIS Benchmarks — consensus-based, freely available security configuration guides for AWS, Azure, GCP, Kubernetes, operating systems, and more. Enterprises use them for compliance audits, SOC 2, and cloud posture management. Tools like AWS Security Hub, Prowler, and Checkov evaluate live accounts against CIS controls; this project does the same check before deploy by scanning static IaC files.
CIS AWS Foundations Benchmark — what this project uses
The CIS Amazon Web Services Foundations Benchmark is the industry-standard checklist for AWS account hardening. It covers IAM (MFA, least privilege), S3 public access, encryption (EBS/RDS), load balancer TLS, and security group ingress/egress. Our 11 rules are a curated subset of those controls — chosen because they are detectable in Terraform and CloudFormation without calling the AWS API.
Static IaC vs live CIS scanning
Live scanners (Prowler, Security Hub) query AWS APIs on a running account. This auditor parses .tf and .yaml files at CI time — shift-left guardrails before anything is applied. Trade-off: catches declared misconfigurations, not drift after deploy. Production would run both.
Rule → CIS theme mapping
PUBLIC_S3_BUCKET — CIS AWS §2.1 S3 Block Public Access / no public ACLs
OPEN_ALL_PORTS · OPEN_SSH · OPEN_RDP · UNRESTRICTED_OUTBOUND — CIS AWS §5.x security group ingress/egress restrictions
UNENCRYPTED_EBS · UNENCRYPTED_RDS — CIS AWS §2.2 EBS encryption · §2.3 RDS encryption at rest
NO_MFA · WEAK_IAM_POLICY — CIS AWS §1.x IAM MFA enforcement · least-privilege policies (no Action: "*")
HTTP_LISTENER — CIS AWS §4.x ELB/ALB — encrypt traffic in transit (HTTPS, not plaintext HTTP)
HARDCODED_SECRET — CIS / OWASP best practice — secrets never in source code; use Secrets Manager or SSM Parameter Store

Every "why did you choose X?" question — answered. Structure: chosen → alternatives → rationale → trade-off.
Why CIS Benchmark rules?
CIS-inspiredcustom rulesOWASP only
CIS Benchmarks are the industry lingua franca for cloud compliance — auditors, Security Hub, and enterprise buyers all recognise them. The AWS Foundations Benchmark maps directly to the misconfigurations in our sample files (public S3, open SSH, unencrypted EBS). Custom rules would be harder to defend; OWASP alone misses infrastructure-specific controls like security groups and RDS encryption.
ILD — Industry standard · IaC-detectable subset · Defensible in compliance conversations
Trade-off: static IaC scan only — does not catch post-deploy drift. Pair with live scanners in production.
Why FastAPI over Flask?
FastAPIFlaskDjango REST
Auto OpenAPI docs at /docs with zero extra work — critical for demo. Pydantic v2 validation built in. Async-native for scaling. The JD mentioned FastAPI in examples.
OAP — OpenAPI auto · Async-native · Pydantic built-in
Trade-off: more initial complexity than Flask
Why SQLite over PostgreSQL?
SQLitePostgreSQLMongoDB
Zero setup — no database server needed. SQLAlchemy abstracts the DB entirely — swap to PostgreSQL with one config line. Challenge required free-tier local deployment.
ZOL — Zero setup · One-line Postgres swap · Local challenge fit
Trade-off: no concurrent writes. PostgreSQL swap = one line when needed.
Why Streamlit over React?
StreamlitReactJinja2 HTML
Professional dashboard from a single Python file. No frontend build tooling. React would take 45+ minutes just on scaffolding. FDE means shipping working solutions fast.
SFF — Single Python file · Fast to ship · FDE speed wins
Trade-off: less customisable. No real-time updates without polling.
Why python-hcl2 for Terraform?
python-hcl2regex parsingpyhcl (unmaintained)
Most actively maintained HCL2 parser in Python. Handles nested blocks, for_each, dynamic blocks. Alternatives are unmaintained or require shelling out.
MND — Maintained · Nested blocks · Dynamic blocks
Trade-off: v8 quoting behaviour needed custom _unquote() helper.
Why risk score capped at 100?
0-100 cappedunbounded pointsCVSS style
0-100 is intuitive and universally understood. Capping at 100 means the display is always meaningful — 100 always means "critical, act now" regardless of violation count.
IMA — Intuitive scale · Meaningful at 100 · Action trigger clear
Trade-off: can't distinguish 3 vs 10 critical findings from score alone. Findings table provides that detail.
Why redact secret values?
Value redactedstore for debugginghash the value
A security tool that stores the secrets it finds would itself be a security risk. Resource name + attribute is sufficient for remediation. Value adds no value, adds significant risk.
DRR — Detect only · Remediate by resource name · Risk if we store secrets
Trade-off: engineers must check original file. This is intentional, not a limitation.
Why local deployment only?
LocalHuggingFace SpacesRender free tier
Challenge warned about cloud costs — zero risk by staying local. Also appropriate for a security tool — you wouldn't send client infrastructure files to a third-party service.
CLO — Cost zero · Local files stay local · Offline demo safe
Trade-off: not publicly accessible without a tunnel. For demo, screen share is sufficient.
Why Claude Code over Cursor?
Claude CodeCursorGitHub Copilot
Terminal access — can run tests and fix failures autonomously. Maintains file context across a full session. The challenge accepted all three; Claude Code gives the most end-to-end autonomy.
TAF — Terminal runs tests · Autonomous fixes · Full session context
Trade-off: more tokens per turn than inline Copilot suggestions.
