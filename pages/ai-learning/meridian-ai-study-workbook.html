Meridian AI, read from the code

A procurement assistant with two features: answer questions from uploaded PDFs (RAG) and run a three-agent purchase audit. This workbook walks through how it works, what it does for users, how well it meets non-functional needs, and what you could change. Start with the Technical tab and use the demos.

Architecture map

backend/api/main.pybackend/api/endpoints.pybackend/config/settings.py

One FastAPI process serves the REST API and, inside Docker, the built React app. The API calls two subsystems: the RAG pipeline (ingest PDFs, answer questions) and the audit agents. Both use one chat model. Embeddings, the vector store and the document store change with APP_MODE. Click a box.

The local / cloud switch

config/settings.py:37rag/embeddings.py:28-45rag/vector_store.py:56-62rag/document_store.py

settings.is_cloud is the only branch point. Every module that touches storage asks it. The default is local, which needs only a Gemini API key. cloud adds Vertex AI Vector Search, a Cloud Storage bucket and Vertex embeddings. The mode is read once and the clients are cached with lru_cache, so changing APP_MODE needs a restart.

Demo · what changes with the mode (use the local / cloud switch at the top)

Indexes are not interchangeable. Local vectors come from gemini-embedding-001, cloud vectors from text-embedding-005. Both are 768 dimensions, but the models differ, so a Chroma folder cannot be copied into the cloud index. Clear .meridian/chroma before re-indexing after a model change. VERIFIED

Ingestion: PDF to vectors

rag/data_ingestion.py:21-55rag/document_store.py:22-30api/endpoints.py:137-184
1 · LoadPyPDFLoader reads one document per page. A bad file raises IngestionError (HTTP 422).
→
2 · LabelEvery page gets source = doc://<file> from source_key().
→
3 · ChunkRecursive splitter, 1000 characters, 100 overlap.
→
4 · IDsha1(source|page|position) so the same file overwrites itself.
→
5 · Embed + storeadd_documents(chunks, ids=ids). One embedding call per batch to Gemini or Vertex.

Demo 1 · chunker (re-implementation of the splitting idea; separators are dropped for clarity) DEMO

Highlighted text at the start of a chunk is the overlap it shares with the previous chunk. Overlap stops a sentence from being cut in half at a boundary. It also means about 10% of the text is embedded twice at the real settings.

Demo 2 · why stable chunk IDs and one source key matter DEMO

The ID is a SHA-1 of source|page|position. Upload and "index stored files" are two paths to the same PDF. Compare what happens when the two paths name the file differently and when they share source_key().

Edge case to think about. position is the chunk's index across the whole file, not within a page. If you edit a PDF so it has fewer chunks, the old high-numbered IDs are never overwritten and stay in the store as orphans (INFERRED from the ID formula and upsert-by-ID behaviour; not tested). Scanned PDFs yield zero chunks and are reported as "skipped". There is no OCR. INFERRED
Improvement options
A · Delete-then-add per source. Remove all chunks whose source matches before adding, so edits cannot leave orphans.
effort Mplan N7risk: touches stored data
B · Hash the file. Store a content hash per source and skip indexing when it has not changed. Saves embedding cost on repeated uploads.
effort Mplan N7
C · OCR fallback. When a page has no text, run OCR so scanned policies become searchable.
effort Mnew ideaadds a dependency
D · Structure-aware chunks. Split on headings and keep the heading in the chunk metadata, which helps both retrieval and citations.
effort Mplan L1re-index needed

Retrieval: three ways to find context

rag/retrieval.py:53-83rag/retrieval.py:106-121

The chain is one LCEL pipeline: retriever | format_docs and the question go into a prompt, then the chat model, then a string parser. The only choice is the retriever, picked by the retriever_type field. An unknown name falls back to similarity and is logged.

Demo · compare the strategies on a toy corpus DEMO

Ten invented policy chunks for the fictional Aldermoor Industries. Scoring is keyword overlap, not embeddings, and the rewrites are canned. What it shows accurately is the shape of each strategy and how many model calls it makes.

similarity · k=3
Vector search returns the 3 nearest chunks even when none is relevant. Cheapest: 1 embedding, 1 chat call.
multiquery
The chat model writes 3 rephrasings (structured output), all 4 queries are searched, results are merged and de-duplicated by text. 4 embeddings, 2 chat calls.
contextual · k=10
Fetch 10 chunks, then one chat call per chunk copies only the relevant sentences or says NO_OUTPUT. 1 embedding, 11 chat calls. Slowest and most expensive.
The API returns {"answer": ...} only (schemas.py:38). The retrieved passages and their doc:// labels are sent to the model but never returned, so a user cannot check where an answer came from. VERIFIED
Improvement options
A · Return sources. Add sources: [{source, page}] to QueryResponse, then show citation chips in the UI. Smallest change with the biggest trust gain.
effort Splan L1
B · MMR or hybrid search. Maximal Marginal Relevance reduces near-duplicate chunks. Hybrid (keyword + vector) helps with exact terms like part numbers and clause IDs.
effort Mplan L1
C · Reranker. Fetch 20, rerank with a cross-encoder or a cheap model, keep 4. Better precision than raising k.
effort Mplan L1
D · Cheaper model for rewrite and extraction. The 11 calls in contextual do a simple copy task. A smaller model cuts cost and latency.
effort Splan L5
E · Evaluation harness. 15 to 30 questions with the expected source page. Measure hit rate for each strategy before changing anything else.
effort Mplan L1live calls cost money

Read this before trusting an output. A "CLEARED" from the sanctions tool means "the model does not recall this name". It is not a compliance control. The CFO memo is built on those texts.

Middleware around every agent

agent/middleware.py:54-68config/settings.py:66-68

LangChain v1 middleware wraps the agent loop. Order matters: the list is applied top to bottom. All three agents share the same stack.

Demo 1 · PII redaction on the request text DEMO

Config: email → redact, credit card → mask, both with apply_to_input=True. Only input is covered. Names, phone numbers and bank account numbers are not detected. Exact replacement text comes from the library; the output above is an approximation.

A · Custom PII detectors. Add rules for phone numbers, IBANs and tax IDs, and run redaction on tool output too.

B · Budget by cost, not count. Count tokens per audit and stop above a ceiling.

Our own exceptions become clean responses in main.py: ConfigurationError → 503 and IngestionError → 422. Anything else inside a route is caught by except Exception and returned as 500 with detail=str(e), which is the raw library message.

    
The static-file catch-all in main.py:82-89 resolves the real path and checks it starts with the dist folder before serving. That blocks ../ path traversal. It is a good pattern to copy.

    
CORS is allow_origins=["*"] with allow_credentials=True, and there is no authentication. Anyone who can reach the service can run audits and spend your Gemini quota. VERIFIED

    
Improvement options

      
A · Stop leaking exception text. Return a fixed message plus a request ID and log the traceback. Seen live: a billing failure put the provider's message and a billing link into a 500 body. 
effort Splan Q3

      
B · Map provider errors. 429 → 429 with Retry-After, 402/403 → 502 with a clear "model provider refused the request". 
effort Snew idea

      
C · Input limits. request_text has no length limit. Add Field(max_length=...), an upload size cap and a page cap. 
effort Splan Q6

      
D · Access control. Shared API key via a FastAPI dependency (hours), Cloud IAP or Cloud Run IAM in cloud mode, or OIDC with per-user rate limits. The right one depends on who the users are. 
effort Mplan N1needs your decision

      
E · Real readiness check. Keep /health for liveness. Add /ready that confirms config is present and the store opens. 
effort Splan DR-2

Logging and observability
logger/custom_logger.pyagent/middleware.py:36-51

    
structlog writes JSON lines to the console and to ./logs/<timestamp>.log. A processor adds a severity field so Cloud Logging reads levels correctly. In cloud mode the file is also uploaded to Cloud Storage on shutdown, because Cloud Run's disk disappears.

    
The repo rule is to log sizes and IDs, never user content. Examples: query_chars, answer_chars, arg_names, result_chars, error_type. The retrieval, agent and middleware logs follow it. The error handlers in main.py log str(exc), which can contain provider text.

    
Improvement options

      
A · Request ID. Middleware that adds an ID to every log line and every error response. 
effort Splan N8

      
B · Metrics. Count model calls, tool calls, latency and estimated tokens per audit and per question. This is how you would see the 11-call retriever in practice. 
effort Mplan N8

      
C · Move logs out of the document bucket. A separate bucket gets its own permissions and retention. 
effort Mplan L3

      What the system does for its users
      
  
      Aldermoor Industries (fictional) buys equipment from vendors in many countries. A procurement analyst needs two things: quick answers from policy documents, and a second opinion on a purchase request before payment. Meridian provides both. There are no user accounts, so everyone who can open the app sees the same documents.

      Business rules, and who enforces them
      
  
      Only the FX check is enforced by code. The others are instructions in a prompt, so the model applies them and the outcome can vary.
      
  
      
    
      FX hedge check IN CODE
      
      
      variance = |rate used − market| ÷ market; above 5% is an alert (tools.py, validate_fx_hedge).
      
      
      
      
      
    
      Credit score bands IN PROMPT
      
      
      The prompt asks for 75–100 LOW, 50–74 MODERATE, 0–49 HIGH, and 45 for an unknown vendor.
      
      
      
      
      
    
      CapEx / OpEx flags IN PROMPT
      
      
      CapEx above 500,000 needs CFO sign-off. OpEx above 100,000 is a possible misclassification.
